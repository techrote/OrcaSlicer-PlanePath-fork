## Remaining implementation decisions

The key decision is whether state carry-over should be preserved in the neutral refactor or fixed in a separately reviewed behavior change. My recommendation is separate commits/issues: characterize, refactor without drift, then fix with mixed-region regression tests. Similarly, changing low-density explicit-order semantics, bridging support policy for arbitrary future curves, or default SpiralInset direction is outside a membership refactor.

A future script descriptor must decide whether source order means path-list order, direction, loop starting point, or all three; self-intersections and multiline offsets can make nearest-source-position reconstruction ambiguous. That requires adapter/order tests, not runtime selection. The future Turning policy may need independent direction preference versus sampling/repair. Neither question needs #8's Lua outputs to finish PP003.

The complete full-checkout switch search, native factory exercise, custom LockedZag emission and final planner-level validation remain unexecuted here. Treat these as implementation acceptance gates, not as negative findings.
